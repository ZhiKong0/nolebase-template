	# 任务目标
	设计一套支持多AI协同工作的文件架构与操作协议。该架构需满足：
	1. 每个AI的 `思考(THOUGHT)`、`执行(EXEC)`、`改动(MOD)` 实时写入并可供其他AI低延迟读取；
	2. 记录必须分级分层，杜绝全量加载导致的上下文爆炸；
	3. 实现“渐进式全貌获取”机制：新AI或新任务仅需读取最新层级内容，通过任务迭代自然沉淀并串联历史全貌；
	4. 所有AI遵循统一的读写边界、指针追踪与摘要生成规则。
	
	# 核心设计规范
	## 1. 三元记录结构化模型
	- 所有操作必须拆分为独立且关联的三元日志：
	  - `THOUGHT`：意图、推理路径、决策依据
	  - `EXEC`：工具调用、API交互、文件读写动作
	  - `MOD`：实际变更的Diff、影响范围、状态结果
	- 强制使用统一Schema（JSON/YAML），包含：`session_id`, `agent_id`, `timestamp`, `type`[T/E/M], `content`, `related_files[]`, `status`, `checksum`
	
	## 2. 实时同步与低延迟读取协议
	- 采用 `流式追加 + 读指针追踪` 机制：实时日志写入 `STREAM_LOG/`，每个AI维护独立 `READ_POINTER.json` 记录已消费偏移量。
	- 实时读取不加载历史内容，仅通过轮询/监听获取 `NEWEST_ENTRY` 指针后的增量数据。
	- 任务运行期间提供 `LIVE_STATE_BOARD.md` 作为轻量状态看板，仅暴露当前进度、阻塞点与关键决策摘要。
	
	## 3. 动态分级体系（防上下文溢出）
	设计5级分层存储，AI仅按需加载对应层级：
	- `L0_STREAM`：实时流日志（仅含指针与最新N条，任务中轮询读取）
	- `L1_ACTIVE`：当前会话全量记录（任务启动时加载，结束后自动打包）
	- `L2_RECENT`：近M个会话或近H小时记录（按需加载，含结构化索引）
	- `L3_DIGEST`：上下文摘要链（每任务结束后生成，串联历史全貌的核心骨架）
	- `L4_ARCHIVE`：冷归档原始日志（仅用于审计/回滚，禁止日常加载）
	- 明确各级触发条件、存储路径、自动归档阈值与清理策略。
	
	## 4. 渐进式全貌获取协议（核心机制）
	- **首次接入/新任务**：AI仅读取 `L3_DIGEST/latest_summary.md` + `L1_ACTIVE` 新记录。
	- **任务完成时**：AI必须执行 `CONTEXT_DIGEST` 流程：提取本次关键决策、失败教训、架构变动，生成 `digest_{session_id}.md` 并追加至 `L3_DIGEST/` 链尾。
	- **迭代累积**：下次任务自动加载最新摘要链，形成 `L3 → L3 → L3` 的知识链。随着任务推进，AI无需重读原始日志即可通过摘要链“拼出”全局演进全貌。
	- 强制规定摘要字数上限、关键信息保留率与跨Agent可见性权限。
	
	## 5. 跨Agent读写边界与并发控制
	- 严格划分只读区、可写区、流日志区、摘要区。
	- 禁止AI直接修改他人活跃文件或覆盖 `L3_DIGEST` 历史节点。
	- 并发写入采用追加模式+原子重命名，冲突时写入 `CONFLICT_LOG.md` 并触发仲裁流程。
	- 所有写入必须附带 `agent_id` 与 `session_id`，确保溯源隔离。
