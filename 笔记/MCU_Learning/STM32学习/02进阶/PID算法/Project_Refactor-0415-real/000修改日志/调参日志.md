## v4 固件审查详情 (2026-04-10)

### v4a: 启用 BNO085 gyro + D项改用 gyroZ
- **T042**: yaw 冻结在 16.3°, 22.5分
- **根因**: 软件 I2C 带宽不足，两个 20ms 报告并发导致 game_rot_vec 包丢失
- **结论**: ❌ 回退

### v4b: DEADZONE 8→0
- **T043**: 完全失稳, yaw±90°, hd 饱和±20, 26.4分
- **根因**: DZ=8 是隐性增益衰减器(15-36%), AKP/AKI 在此衰减下调出, 去掉后相位裕度变负 → 发散
- **结论**: ❌ 回退

### v4c: core==0修复 + core四舍五入 (DZ=8保留)
- **T044**: 15s 全程CRUISE, 75.9分, yaw±2.3°, max_lat=303
- **结论**: ✅ 稳定

### v4d: + 快速yawRate(控制循环内差分) + KEY1修复
- **T045** (AKD=0): **80.3分**, yaw±1.7°, max_lat=155, yaw积分=9.52°·s ★ v4最高分
- **T046** (AKD=0.03): 71.7分, yaw±2.3°, max_lat=364
- **T047** (AKD=0.01): 53.4分, yaw±8.3°, 3s周期振荡

### v4e: 事件驱动快速 yawRate (修复 v4d 噪声)
v4d 的 predictedYaw 差分有外推阶跃噪声。v4e 改为只在 `g_lastImuTick` 变化时从 `g_imu.yaw` 差分, α=0.5 LPF, ~30ms 延迟。

- **T049** (AKD=0): **81.3分** ★★★ v4 最高分, yaw±1.2°, max_lat=222
- **T051** (AKD=0.01): 75.1分, 航向分相似(25.1 vs 25.6), 轨迹分-6分(过零3次vs11次→单侧漂移)
- **T050** (AKD=0.03): 66.3分, 起步yaw=4.2°

噪声已解决, 但 D 项仍无益: PI 已将 yaw 控制在 ±1.2°, D 项对抗修正→减慢漂移修复。

### v4f: Deadzone-on-core 方案
尝试将 deadzone 从单轮移到 core 上, 保留 diff。
- **T052** (AKD=0): **23.6分**, 完全失稳, yaw±80°
- **根因**: 低侧PWM<5不转→单边驱动→正反馈, 与 T043 (DZ=0) 相同根因

### v4g: Symmetric Boost 方案
当低侧<DZ时, 双轮同时加相同偏移, 保留 diff。
- **T054** (AKP=0.5): **23.2分**, 完全失稳, yaw±92°
- **T055** (AKP=0.35): **24.1分**, yaw锁死-24°, hd饱和+20
- **根因**: boost 在斜坡期将 core=3 → 平均PWM=10, 速度环无法跟踪→振荡

### AKD 不可调的完整因果链
1. 电机物理死区: PWM<5 不转 → 必须有 DEADZONE=8
2. DEADZONE=8 在起步期(core<8)杀死 diff → D 项修正在最需要的时候被消灭
3. 稳态期(core≈10) D 项可通过, 但 PI 已足够好(yaw±1.2°) → D 无益
4. 去掉/绕过 deadzone 的三种方案全部导致失稳

**最终结论: AKD=0 是当前硬件的确定最优值。**

### KEY1 修复
`transition_start()` 原来只调 `DualLoop_ResetAll()` (重置积分), 不重新加载PID增益。
串口调参后按KEY1会使用串口设的参数而非config.h默认值。
修复: 改为调 `DualLoop_LoadStraightDefaults()` / `DualLoop_LoadTrackDefaults()`, 确保KEY1始终用最佳默认参数。
