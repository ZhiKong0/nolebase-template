## Decisions Made
| Decision | Rationale |
|----------|-----------|
| 先提炼五路转角判定，再映射到八路 | 避免直接硬改目标工程导致逻辑漂移 |
| 保留直线/循迹双模式 | 用户明确要求两种模式并存 |
| 保留目标工程主循环和串口/显示接口，只重写 `line_track` | 降低对直线模式和已有调参链路的影响 |
| 八路正常循迹继续使用加权位置 + PD，转角改回五路式“全灭后按历史转向” | 既保留目标工程的双模式框架，也满足用户要求的五路转角逻辑 |
| 第二轮整改改为“8 路输入压成 5 路等效信号，再直接复刻五路状态机” | 用户明确要求彻底舍弃旧循迹判断，不能再保留先前的八路自定义状态机 |
| 串口实验记录链路只补最小必要 MCU 改动，不强行移植 OLED 实验号显示 | 用户目标是“按键/串口触发后自动落盘”，不是重做整套 UI |
| 继续沿用参考工程的 `experiment_logger.py` 协议和目录结构 | 这样 `COM18` 常驻采集、实验编号同步、`000Data/serial_runs/experiments` 文件命名都能直接复用 |
