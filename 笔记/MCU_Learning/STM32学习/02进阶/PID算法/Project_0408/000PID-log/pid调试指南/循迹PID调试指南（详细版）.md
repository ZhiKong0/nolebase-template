# 循迹 PID 调试指南（详细版）

## 1. 文档目标

这份文档用于指导当前 `Project_Refactor` 工程中的**循迹模式 PID 调试**。

这里说的“循迹模式”，是指：

- 小车根据 `S1~S8` 八路循迹传感器判断黑线位置
- 通过差速控制让车体回到中线
- 串口可下发参数、启动实验、采集数据
- 上位机可通过 `exp_runner_track.py` 自动跑实验
- 采集结果可通过 `track_trajectory_analyzer.py` 做离线分析

这份文档的核心目标不是只告诉你“把 `Kp` 调大还是调小”，而是把**完整调试方法论**写清楚：

- 先看什么
- 后调什么
- 依据什么现象判断
- 如何结合串口数据做分析
- 如何避免把问题误判成 PID 问题

---

## 2. 当前循迹模式的控制链路

先把控制链路讲清楚，后面的调试才不会乱。

### 2.1 传感器输入

当前固件中使用了 8 路数字量循迹传感器：

- `S1`
- `S2`
- `S3`
- `S4`
- `S5`
- `S6`
- `S7`
- `S8`

固件会把这 8 路状态组成 `sensorBits`，并根据加权位置算出：

- `linePositionRaw`
- `linePosition`

其中：

- `linePositionRaw` 是按当前灯状态直接算出来的位置
- `linePosition` 是做了轻微滤波后的结果

### 2.2 中线语义定义

这次循迹模式的分析规则里，必须牢记下面这组语义：

- **`S4` 和 `S5` 同时亮**
  - 代表**最理想、最稳的中线状态**
- **`S4` 单独亮**
  - 代表**右偏**
- **`S5` 单独亮**
  - 代表**左偏**

这是你后续观察数据时最核心的判断依据。

### 2.3 控制输出

固件当前使用的是单层循迹 PID 结构：

- 输入：`linePosition`
- 误差：`lineError`
- 输出：`linePidOut`
- 混控：
  - `left = base + diff`
  - `right = base - diff`

其中：

- `base` 主要由 `targetSpeed` 决定
- `diff` 由 `Kp/Ki/Kd` 和位置误差共同决定

### 2.4 当前丢线行为

当前这版固件已经**删除了主动找线逻辑**。

也就是说：

- 短暂丢线先做轻微去抖
- 连续确认丢线后
  - **直接停输出**
  - **不再做自动搜索转向**

因此，如果你后续在数据里看到：

- `line_missing_ratio` 很高
- `run=1` 期间频繁出现 `S1~S8` 全灭
- 左右输出突然归零

那么首先不要怀疑 PID，而要优先怀疑：

- 车真的跑出了线
- 传感器高度/角度不对
- 路面线宽、反光、阈值有问题
- 基础速度太高，来不及修正

## 3. 当前调参入口

结合当前工程实现与实验脚本，循迹模式建议只把以下参数作为常规调参入口：

- `ts`
- `kp`
- `ki`
- `kd`
- `pwm_max`

含义如下：

### 3.1 `ts`

- 表示循迹的基础推进量
- 本质上决定了小车“默认向前跑”的速度基线
- 它不是传统意义上物理速度闭环目标，而更接近“基础 PWM 档位”

### 3.2 `kp`

- 决定小车看到偏差后，立即往回拉的力度
- 这是循迹里最敏感、最先调的参数

### 3.3 `ki`

- 用于消除长期固定方向偏差
- 只在 `kp` 已经基本调好后，才考虑极小幅加入

### 3.4 `kd`

- 用于增加阻尼、减少来回摆动
- 适合在已经能回线、但回线过程太冲的时候使用

### 3.5 `pwm_max`

- 限制左右轮最大输出
- 用来约束差速过猛和整体速度过高的问题
- 是一个非常实用的“安全阀”参数

---

## 4. 调参前必须确认的前提

在你真正开始调 PID 之前，先确认下面这些前提满足。

### 4.1 传感器语义正确

你至少要现场确认下面几件事：

- 黑线位于正中时，`S4/S5` 是否最容易同时亮
- 车体轻微右偏时，是否更容易出现 `S4` 单独亮
- 车体轻微左偏时，是否更容易出现 `S5` 单独亮
- 左右外侧传感器亮灭顺序是否符合直觉

如果这件事本身不对，那么后面 PID 调得再漂亮，小车也不会稳定。

### 4.2 左右轮动力链路基本正常

至少要满足：

- 左轮能稳定转
- 右轮能稳定转
- 左右编码器有基本可用的数据
- 不存在“一侧实际在动但编码器长期为 0”的情况

如果某一侧编码器不可信，分析脚本里的轨迹重建会失真，你会很容易把硬件问题误判成 PID 问题。

### 4.3 串口回传稳定

你要确认 `TRK` 行能持续输出这些值：

- `el`
- `er`
- `y`
- `s1~s8`

如果串口输出本身断断续续、乱码、丢包严重，那么离线分析结论也不可靠。

### 4.4 先做低风险测试

建议按以下节奏来：

1. 先悬空看传感器逻辑
2. 再低速地面短距离测试
3. 先跑 5s~10s
4. 现象稳定后再跑更长时间

不要一开始就高速、长时间跑，否则很容易把多个问题搅在一起。

---

## 5. 推荐的循迹调参顺序

循迹 PID 不建议一上来就同时调 `P/I/D`。

推荐严格按照下面顺序做：

1. **先定 `ts` 和 `pwm_max`**
2. **只调 `kp`**
3. **必要时加少量 `kd`**
4. **最后才考虑 `ki`**

---

## 6. 第一步：先定基础速度 `ts` 和上限 `pwm_max`

### 6.1 为什么要先定速度

如果基础速度过高，会出现两个后果：

- 偏差刚出现，车已经冲过去了
- 你会误以为是 `kp` 太小，其实是速度太高

如果基础速度过低，又会出现：

- 小车几乎不走
- 编码器数据过小，轨迹分析噪声相对更大
- 看不出真实循迹能力

### 6.2 推荐做法

先把 `kp/ki/kd` 设得比较保守：

- `kp` 取小值
- `ki = 0`
- `kd = 0`

然后先调整：

- `ts`
- `pwm_max`

目标是得到一个**不至于太冲、但车能顺畅前进**的基础工况。

### 6.3 判断标准

#### `ts` 太小

现象：

- 车走得很慢
- 线偏了但不容易看出动态修正过程
- 部分地面可能还没克服静摩擦

#### `ts` 合适

现象：

- 小车能稳定向前走
- 轻微偏差能被明显看见
- 即使修正，也不会一下子甩太狠

#### `ts` 太大

现象：

- 一旦偏离就很容易冲出线外
- 很容易出现突然全灭、丢线即停
- 你会感觉车“来不及反应”

### 6.4 `pwm_max` 的作用

`pwm_max` 不是核心控制参数，但很有价值：

- 它能限制左右轮最大输出
- 可以防止调参早期差速过猛
- 能减少“突然拧头”或瞬时过冲

实操建议：

- 前期可以把 `pwm_max` 设得保守一些
- 等 `kp/kd` 调顺后，再考虑适当放大

---

## 7. 第二步：只调 `kp`

这是循迹调参中最关键的一步。

### 7.1 初始建议

先把：

- `ki = 0`
- `kd = 0`

只保留 `kp`。

### 7.2 `kp` 的作用

`kp` 决定了偏差出现后，差速修正的第一反应强度。

可以把它理解成：

- 看见偏了，立刻往回拽的力度

### 7.3 现象判断

#### `kp` 太小

常见现象：

- 小车偏了以后修不回来
- 或者修得很慢
- 跑着跑着就越来越偏
- 数据里 `s4_only_ratio` 或 `s5_only_ratio` 长时间偏高
- `sensor_score` 的平均值长期偏在一侧

#### `kp` 合适

常见现象：

- 一旦偏离，中线附近能及时拉回
- `S4/S5` 同时亮的比例开始明显提升
- 车不容易冲出线
- 轨迹中累计横向偏移增长变慢

#### `kp` 太大

常见现象：

- 车不是平滑回正，而是突然猛拧一下
- 经常从右偏一下修成左偏，再从左偏修成右偏
- 肉眼看起来像“抽一下”“甩一下”
- 数据里左右偏状态切换过于频繁
- `s4_only_ratio` 和 `s5_only_ratio` 都不低，但 `s4s5_both_on_ratio` 并没有提升

### 7.4 调整原则

建议每次只做小步改动，例如：

- `0.05`
- `0.1`
- 或最多 `10%~20%`

不要一口气翻倍。

### 7.5 实用判断标准

如果你想知道一个 `kp` 值是否值得保留，优先看下面三件事：

- `s4s5_both_on_ratio` 是否升高
- `line_missing_ratio` 是否降低
- 车体是否从“偏了不回”变成“能回但不猛甩”

---

## 8. 第三步：必要时引入 `kd`

### 8.1 什么时候加 `kd`

只有在下面这种情况下，才建议加 `kd`：

- `kp` 已经让车具备“看见偏差会回”的能力
- 但回正动作过猛
- 会出现左右来回摆
- 或者到某些位置突然抽动

### 8.2 `kd` 的作用

`kd` 的本质是增加阻尼。

它适合解决的问题是：

- 回正太冲
- 过线太多
- 左右来回摆

### 8.3 现象判断

#### `kd` 太小

- 回线会显得太冲
- `kp` 一大就容易甩
- 左右摆动抑制不住

#### `kd` 合适

- 回正更平滑
- 不会一看到偏差就猛拧
- `s4_only -> s4+s5 -> s5_only` 这种切换变得更缓和

#### `kd` 太大

- 系统会变钝
- 明明偏了，却不愿意快速回正
- 容易导致“修正晚半拍”
- 低速时表现尤其明显

### 8.4 建议

- `kd` 一定小步加
- 如果你加了 `kd` 之后明显感觉“迟钝、拖泥带水”，就说明加多了

---

## 9. 第四步：最后才考虑 `ki`

### 9.1 `ki` 不是先手参数

在循迹里，`ki` 不是第一优先项。

绝大多数情况下：

- 先靠 `kp`
- 再靠少量 `kd`

就能解决主要问题。

### 9.2 `ki` 适合解决什么问题

只有当你已经确认下面这件事时，才考虑加 `ki`：

- 车整体已经能循迹
- 但长期稳定地向同一侧偏一点
- 比如总是更容易出现 `s4_only` 或总是更容易出现 `s5_only`

这时候小积分可以帮助系统抵消固定偏差。

### 9.3 `ki` 太大时的表现

- 低频慢摆
- 偏一会儿、积一点、再整体往另一边顶过去
- 很容易出现“不是快抖，而是慢慢左右晃”

### 9.4 结论

- `ki` 只建议**极小幅**使用
- 如果一上来就加 `ki`，很容易把问题搞复杂

## 10. 推荐实验流程

当前工程已经有一整套循迹实验链路：

- `exp_runner_track.py`
- `track_trajectory_analyzer.py`
- 数据目录：`000Data/循迹数据`

建议每次调参都按固定流程执行。

### 10.1 单次实验命令示例

```bash
python exp_runner_track.py --port COM18 --ms 10000 --ts 26 --kp 0.5 --ki 0.0 --kd 0.0 --pwm-max 72 --realtime
```

调参时建议：

- 同一轮只改一个主参数
- 其他参数保持不变
- 每一组都保存对应数据

### 10.2 分析命令示例

```bash
python track_trajectory_analyzer.py --data-dir "000Data/循迹数据"
```

或者指定单次原始数据：

```bash
python track_trajectory_analyzer.py --raw "000Data/循迹数据/xxx_raw.txt"
```

### 10.3 每轮实验建议记录

- `s4s5_both_on_ratio`
- `s4_only_ratio`
- `s5_only_ratio`

## 11. 如何读懂分析结果

### 11.1 `s4s5_both_on_ratio`

这是当前循迹调参中最重要的指标之一。

含义：

- `S4` 和 `S5` 同时亮的样本比例

解释：

- 比例越高，代表车越经常处于理想中线附近
- 这通常是“参数变好”的强信号

### 11.2 `s4_only_ratio`

含义：

- `S4` 单独亮的比例

解释：

- 对应**右偏**
- 如果这个比例明显高于 `s5_only_ratio`，说明整体更容易右偏

### 11.3 `s5_only_ratio`

含义：

- `S5` 单独亮的比例

解释：

- 对应**左偏**
- 如果这个比例明显高于 `s4_only_ratio`，说明整体更容易左偏

### 11.4 `line_missing_ratio`

含义：

- 传感器判为丢线的比例

解释：

- 当前固件中，丢线后不会找线，而是停输出
- 所以这个值一高，说明当前参数组合已经不安全或不可靠

### 11.5 `mean_ed`

含义：

- 左右编码器差值的平均趋势

解释：

- 可以辅助判断左右驱动是否长期不对称
- 但它不是循迹唯一指标，必须结合 `s1~s8` 一起看

### 11.6 `final_y` / `sensor_y_accum`

含义：

- 是对整段运行中横向趋势的相对描述

解释：

- 如果长期偏右，这两个量通常也会表现出明显侧向累积
- 它们很适合做“同条件不同参数”的横向对比

## 12. 推荐调参节奏

建议按下面这个节奏做。

### 12.1 阶段 A：先找能稳定跑的基础速度

固定：

- `kp` 小值
- `ki = 0`
- `kd = 0`

只调：

- `ts`
- `pwm_max`

目标：

- 不容易一上来就冲飞
- 车能连续稳定采到线

### 12.2 阶段 B：只调 `kp`

固定：

- `ki = 0`
- `kd = 0`
- `ts` 不变
- `pwm_max` 不变

逐步增加 `kp`，找出：

- 能及时回线
- 但还没有明显猛甩

### 12.3 阶段 C：少量加 `kd`

当你看到：

- 已经能回线
- 但回线过程太冲、太抖

再加少量 `kd`。

### 12.4 阶段 D：最后才引入很小的 `ki`

当你确认：

- 整体已经能跑
- 只是长期偏某一侧

再加极小 `ki`。

## 13. 典型现象与判断表

| 现象 | 可能原因 | 优先处理 |
| :--- | :--- | :--- |
| 偏了也不怎么回 | `kp` 太小；`ts` 太高导致来不及修 | 先增 `kp`，必要时降 `ts` |
| 一看到偏差就猛甩 | `kp` 太大 | 先降 `kp` |
| 能回，但左右来回摆 | `kp` 稍大且阻尼不足 | 小幅加 `kd`，或略降 `kp` |
| 不怎么摆了，但变钝 | `kd` 太大 | 降 `kd` |
| 长期更容易右偏 | 机械不对称；固定偏差；`ki` 仍为 0 | 先确认硬件，再小幅加 `ki` |
| 长期更容易左偏 | 同上 | 同上 |
| 经常突然停住 | 实际是丢线；当前固件丢线即停 | 先降 `ts`，再看传感器安装与线宽 |
| 数据里 `s4s5_both_on_ratio` 很低 | 大部分时间不在中线附近 | 先调 `kp` / `ts` |
| `s4_only_ratio` 和 `s5_only_ratio` 都高 | 左右来回甩 | 降 `kp` 或加少量 `kd` |
| `line_missing_ratio` 很高 | 速度太快、传感器几何不对、线环境差 | 先处理工况，再谈 PID |

## 14. 必须避免的几个误区

### 14.1 误区一：一上来同时调 P、I、D

这样做的后果是：

- 你根本不知道现象是谁造成的
- 结果经常是越调越乱

### 14.2 误区二：一丢线就继续怀疑 PID

当前固件里：

- 丢线就是停
- 不再搜索找线

所以一旦丢线比例高，优先看：

- `ts` 是否太高
- `kp` 是否还来不及修正
- 传感器安装是否合理
- 黑线宽度与反光条件是否合适

### 14.3 误区三：过度依赖肉眼，不看数据

肉眼很容易被瞬时现象误导。

建议最少同时看：

- 现场现象
- `s4/s5` 统计
- `line_missing_ratio`
- 编码器差
- 轨迹累计偏移

### 14.4 误区四：把硬件问题当成 PID 问题

如果存在下面任意一种情况，优先排硬件：

- 一侧编码器长期异常
- 传感器触发顺序不合理
- 某一侧轮子机械阻力明显更大
- 串口数据本身丢失严重

## 15. 推荐的实操模板

下面给你一个比较稳的现场节奏。

### 第 1 轮：基础安全轮

目标：

- 确认车能跑
- 确认不会一上来就丢线

做法：

- 低 `ts`
- 小 `kp`
- `ki=0`
- `kd=0`

### 第 2 轮：建立回线能力

目标：

- 让车明显具备回中线能力

做法：

- 保持 `ts` 不变
- 逐步加 `kp`

### 第 3 轮：抑制过冲

目标：

- 把回线从“能回”变成“回得平顺”

做法：

- 在合适 `kp` 基础上小加 `kd`

### 第 4 轮：修长期固定偏差

目标：

- 消除长距离总朝某一侧偏的问题

做法：

- 硬件确认无大问题后
- 极小幅加入 `ki`

---

## 16. 最终原则总结

调循迹 PID 时，始终记住下面几句话：

- **先把传感器语义看对。**
- **先定基础速度，再调 PID。**
- **先 `Kp`，再 `Kd`，最后才考虑 `Ki`。**
- **`S4+S5` 同时亮比例，是很重要的好坏指标。**
- **`S4` 单亮偏右，`S5` 单亮偏左。**
- **当前固件丢线即停，不会自动找线。**
- **丢线多时先看工况和速度，不要先怪 PID。**
- **同一轮只改一个主参数。**
- **既看肉眼现象，也看离线数据。**
- **现象与理论长期不符时，优先排查硬件和代码逻辑。**

如果你按这套顺序做，循迹调试会比“凭感觉乱试”稳定很多，数据也更容易积累成可复用结论。
