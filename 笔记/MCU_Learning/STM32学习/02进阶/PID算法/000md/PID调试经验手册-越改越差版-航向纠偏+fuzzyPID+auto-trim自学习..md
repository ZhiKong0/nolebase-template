# PID / 航向控制调试经验手册（STM32 小车直行纠偏）

## 1. 目标与典型现象

### 1.1 目标

- 直线行驶：在不同速度档位下，车能够长距离保持目标航向。
- 抗扰恢复：被外力/地面不均导致偏航后，能在较少摆动次数下回到目标航向。
- 可调可观测：通过串口实时观察关键量，并能在线调参。

### 1.2 常见问题表征（按优先级）

- 启动就偏（“起步右漂/左漂”）。
- 左右来回摆动次数多，收敛慢。
- 纠偏越纠越偏，最后 180° 掉头或原地转圈。
- 偶发不纠偏：偏了但航向纠偏不介入，或者介入太晚。

## 2. 调试总原则（先观测、后调参、再改结构）

### 2.1 先把“观测链路”打通

没有稳定的数据输出时，所有调参都是盲调。

- **必须能稳定输出**：MPU 状态、yaw、yawRate、yawErr、headingCorr、PWM、编码器速度等。
- **串口硬件优先排查**：TX/RX 交叉、GND 共地、波特率一致。

### 2.2 先消灭“系统性错误”，再讨论“参数优化”

- 传感器方向/符号错：会导致正反馈，表现为越纠越偏。
- 航向融合漂移：表现为越跑越偏、纠偏方向时而反。
- 输出饱和：纠偏一上来就打满，导致超调、左右抖。

### 2.3 调参顺序

推荐顺序：

1. **确保 yaw / yawRate 可信**（含零偏校准）。
2. **先调死区 DB**：决定“何时介入纠偏”。
3. **再调纠偏注入强度 HP（HEADING_PWM_GAIN）**：决定“纠偏有多硬”。
4. **再调阻尼 HD（HEADING_YAWRATE_DAMP）**：减少摆动/抖动。
5. **最后调平滑 HS（HEADING_CORR_SLEW_STEP）**：决定变化速度/手感。

## 3. 诊断数据（你必须盯住哪些量）

建议你在 VOFA/HB/STAT 输出里至少包含下列字段（越全越快定位）：

- `mpuOk` / `mpuReadOkCount` / `mpuReadFailCount`
- `yaw`（融合航向角）
- `yawRate`（陀螺 Z 角速度）
- `targetYaw` 或 `headingLockedYaw`
- `yawErr`（航向误差，注意归一化到 [-180,180]）
- `headingCorr`（外环给出的航向纠偏量）
- `diffPwm`（headingCorr 经过增益后的差速注入量）
- `leftTargetPwm` / `rightTargetPwm`
- `leftPwmOut` / `rightPwmOut`（最终输出，含 ramp、限幅、trim）
- `encoder.leftSpeed` / `encoder.rightSpeed` / `encoderDiff`
- `trimPwm` / `trimAuto` / `autoTrimEnabled` / `trimManualOverride`

### 3.1 三个“最关键一致性检查”

- **检查 1：yawErr 与纠偏方向**

  - 当 `yawErr > 0` 时，你的系统应该输出“让车往负方向回去”的纠偏（或反之）。
  - 一旦发现 `yawErr` 增大时 `headingCorr` 也在“推动它更增大”，就是符号/坐标系错。
- **检查 2：diffPwm 注入是否真的影响电机**

  - `headingCorr` 只是一个浮点量不够，必须最终体现在 `left/right PWM` 差值上。
  - 如果 `diffPwm` 有变化但 `PWM` 差值没变化，说明你在混控链路里丢了它。
- **检查 3：饱和与 ramp**

  - 如果 `diffPwm` 或 `PWM` 经常打到限幅，表现会像“抖动/转圈”。
  - ramp（软启动/斜坡）太慢会导致“看起来不纠偏/介入晚”。

## 4. 外环 + 内环结构经验（航向外环 + 速度内环）

### 4.1 双环基本节奏

- 外环（例如 20ms）：融合航向 + 计算 `headingCorr`。
- 内环（例如 10ms）：速度 PI + 把 `headingCorr` 注入差速 + PWM ramp + 输出。

**经验**：

- 外环负责“方向”，内环负责“速度/电机响应”。
- 只要内环能稳定跟随目标速度，外环调参会更线性。

### 4.2 航向融合（gyro + encoder）

- gyro 为主、encoder 为辅。
- encoderYawRate 的**符号**必须严格对齐你的 yaw 正方向。

**经验：编码器差分估算 yawRate 的符号经常是最大坑点**：

- 你需要用一个“已知向左/向右转”的动作，确认：
  - `encoderDiff = leftSpeed - rightSpeed` 时，正负对应的是左转还是右转。
  - `encoderYawRate = encoderDiff * k` 的正负要与 `gyroYawRate` 一致。

### 4.3 死区 DB（yawDeadband）

- DB 太大：纠偏介入太晚，容易累计误差后突然大纠偏，出现发散。
- DB 太小：会“见噪声就纠”，导致左右微抖。

**经验**：

- 你曾观察到 DB 从 1.8 降到 1.6 更稳定。
- DB 的正确意义是“忽略小误差/噪声”，不是拿来解决机械偏置。

## 5. 航向纠偏输出链路经验（如何避免抖动与转圈）

### 5.1 后混控（Post-mix）是更可控的注入点

推荐形式：

- `diffPwm = headingCorr * HEADING_PWM_GAIN`
- `leftTargetPwm -= diffPwm`
- `rightTargetPwm += diffPwm`

优点：

- 纠偏直接体现在差速上，调参直观。
- 不容易与速度 PI 的积分互相“抢控制权”。

### 5.2 限幅与软化（必须有）

- `diffPwm` 限幅：避免一脚打满导致掉头/转圈。
- `headingCorr` 平滑（slew/ramp）：避免外环输出跳变导致左右摆。

### 5.3 yawRate 阻尼（HD）

形式类似：

- `headingCorr -= yawRate * HEADING_YAWRATE_DAMP`

经验：

- 阻尼的作用是减少摆动次数，提升“回正后不反复横跳”。
- 阻尼过大：车会“纠偏不积极/像被刹住”。

## 6. 机械偏置不要用 PID 硬扛：用 trim / auto-trim

### 6.1 现象

- `TRIM=0` 长距离慢慢偏右（或偏左），但纠偏不应该一直去抵消一个“恒定偏置”。

### 6.2 手动 trim（#TRIM=）

- 通过 `trimPwm` 对左右输出做静态微调：
  - `outL = leftPWM + trimPwm`
  - `outR = rightPWM - trimPwm`

经验：

- 手动 trim 用于快速验证“机械偏置确实存在”。
- 但手调不是最终解：不同速度/电池电压/地面摩擦会变化。

### 6.3 自动学习 auto-trim（#AT=）

核心思路：

- 在车运行且状态稳定时（纠偏很小、yawRate 不大），用 `encoderDiff` 的长期偏差去学习 `trimAuto`。
- 将 `trimAuto` 映射/限幅为 `trimPwm`（例如 -5~+5）。

#### 6.3.1 必做：先做 TRIM 正负“方向定性”（避免方向搞反）

目的：确认你定义的 `trimPwm` 正负，分别会让车更偏左还是更偏右。这个结论后续用于判断 auto-trim 学习方向是否正确。

推荐流程（每次只跑 3~5 秒，防止失控）：

1. `#STOP!`
2. `#AT=0!`（先关 auto-trim，避免边跑边改）
3. `#SPD=3!`（固定速度档位，保证可重复）
4. `#TRIM=+3!` + `#RUN!`，观察更偏左/更偏右，立刻 `#STOP!`
5. `#TRIM=-3!` + `#RUN!`，观察更偏左/更偏右，立刻 `#STOP!`

经验：

- 若你观察到 `TRIM=+3` 更偏左、`TRIM=-3` 更偏右，那么“要抵消偏左”就应该让 auto-trim 收敛到 **负 trim**。
- 若方向相反，说明你的混控注入（`outL/outR` 的加减）或电机正反定义有问题，必须先修正符号，否则任何学习/调参都会越调越偏。

#### 6.3.2 为什么“明明有陀螺仪航向控制”，仍然会长期偏一侧？

航向外环（基于 yaw/yawErr/headingCorr）主要解决“动态偏航”（被扰动后拉回）。但机械偏置往往是一个“持续恒定扰动”（轮径差、摩擦差、电机强弱差、电池压降导致两侧响应不一致），会导致：

- 如果死区 DB 存在：小偏差会长期存在并慢慢累计为轨迹偏移。
- 如果外环没有有效 I 项：系统需要保持一个非零 `yawErr` 才能产生足够纠偏来抵消偏置（表现为长期偏一侧）。
- 若 `diffPwm`/PWM 经常饱和：纠偏量算出来也未必真的落实到轮子上。

因此：**trim/auto-trim 的角色**可以理解为“很慢的偏置补偿（相当于外环的低频 I / 前馈）”，它让车在稳定直行时把偏置补掉，外环就不需要长期顶着误差工作。

#### 6.3.3 方案演进（非常关键）：从 encoderDiff 学习切换到 yawErr 学习

你在实车上遇到过典型现象：

- 车肉眼“偏左”，但用 `encoderDiff = leftSpeed - rightSpeed` 做学习信号时，`trimAuto/trimPwm` 反而学到“让车更偏左”的方向（例如学出 `+trim`）。

这说明：在你的场地/车况下，`encoderDiff` 并不能稳定代表“偏航方向”，常见原因：

- 轮胎打滑/地面摩擦差：编码器速度差不等于真实航向变化。
- 左右轮负载差导致的瞬态：加速/减速阶段 encoderDiff 的符号会翻来覆去。
- 编码器计数方向/电机正反定义复杂：虽然你能让车跑起来，但 `leftSpeed/rightSpeed` 的符号体系不一定直观。

因此更稳的做法是：

- **学习信号改为 `yawErr`**（目标航向 - 当前航向），因为 `yawErr` 的符号与“偏左/偏右”是同一件事。
- 在稳定直行时，若车偏左导致 `yawErr` 长期为负，则用 `trimAuto += yawErr * k` 会把 trim 推向负，从而把车往右拉回。

一句话总结：

- `encoderDiff` 更像“执行器侧的观测”，会被打滑/瞬态污染。
- `yawErr` 是“结果侧的观测”，与最终走不走直线直接相关，因此更适合作为 auto-trim 的学习驱动。

#### 6.3.4 yawErr 学习版 auto-trim（推荐模板）

目标：只在“直行稳定段”做慢速学习，避免把动态纠偏学进 trim。

推荐条件（门控 + 保护）：

- 运行中、正常模式（非 speed-only 测试模式）
- 启用 auto-trim 且未手动覆盖（`autoTrimEnabled=1 && trimManualOverride=0`）
- 刚启动一段时间不学习（例如前 500ms）
- `targetSpeed > 0`
- **直行稳定门控**：
  - `|headingCorr| <= 0.3`（外环纠偏很小）
  - `|yawRate| <= 20`（没有明显转向/抖动）
- **yawErr 死区**：`|yawErr| <= 1°` 不学习（只补“长期偏置”，不跟噪声走）
- **yawErr 夹紧**：例如限制到 `[-15°, +15°]` 再积分（防止偶发大误差导致 trim 瞬间跳变）
- `trimAuto` 限幅：例如 `[-5, +5]`，并映射成整数 `trimPwm`

推荐学习公式（示意）：

- `trimAuto += yawErr * k`

其中 `k` 的经验：

- `k` 过大：trim 很快打满，表现为越学越抖/方向突然变。
- `k` 过小：25 秒看不出变化，但好处是稳。
- 经验起点：`k = 0.002`（仍需结合你的 HB 输出周期与 yawErr 量纲微调）。

#### 6.3.5 日志判据（用来判断“有没有学对”）

你每次跑完 25 秒，至少检查：

- `mo`（manual override）
  - 期望：`mo=0`。
  - 如果你发送了 `#TRIM=`，通常会变为 `mo=1`，auto-trim 会暂停，这会让你误以为“学习没生效”。

- `ta/trim` 的趋势
  - 期望：当车偏左时，`ta/trim` 应该逐步走向能抵消偏左的方向（例如你定性后需要负 trim，就应向负收敛）。
  - 若 `ta` 一路朝相反方向走，说明学习信号与真实偏航方向不一致，必须换学习信号或修正符号。

- “是否暴冲打满”
  - 期望：`trim` 不要几秒就到 ±5。
  - 暴冲常见原因：`k` 太大、缺少死区/夹紧、缺少稳定门控。

- “是否把动态纠偏学进 trim”
  - 现象：只要车发生一两次大摆动，`trim` 就永久偏移。
  - 处理：收紧门控（更小 `headingCorr`/`yawRate` 阈值），并提高 `yawErr` 死区。

#### 6.3.6 推荐复测脚本/流程（把调试变成可重复实验）

每次修改算法或参数后，建议固定流程：

1. 物理准备：摆正车体、轮胎清理、地面尽量一致
2. `#STOP!`
3. `#STAT!`（确认串口链路正常、HB 字段齐全）
4. `#CAL!`（让车静止，完成陀螺零偏；否则 yaw 漂移会把学习带偏）
5. `#AT=1!`（确保启用自动学习）
6. `#DB=1.6!`（或你当前稳定值）
7. `#SPD=3!`（固定速度档位）
8. `#RUN!` 跑 25 秒
9. 看日志：`mo=0`、`ta/trim` 趋势、是否饱和、是否抖动

#### 6.3.7 常见坑（你已经踩过的那类）

- “串口没数据”导致误判：先查 TX/RX 是否接反、是否共地、波特率与端口号。
- `#TRIM=0!` 并不是“什么也不做”：它通常会触发手动覆盖标志，导致 auto-trim 暂停。
- 只靠 `encoderDiff` 学习会学反：在打滑/瞬态/符号体系复杂时很常见，建议改为 `yawErr` 学习。
- `trim` 的正负必须用 TRIM=±3 实测定性，否则你会在“错误方向”上越调越偏。

关键保护条件（经验）：

- 运行模式必须是正常模式。
- 刚启动的一段时间不学习（例如前 500ms）。
- `headingCorr` 太大不学习（否则会把动态纠偏“学进 trim”）。
- `yawRate` 太大不学习（转弯/抖动时不学习）。
- 手动 `#TRIM=` 后设置 `trimManualOverride=1`，暂停自动学习；`#AT=1` 重新启用时清除 override。

## 7. 在线调参体系（把调参变成“可重复实验”）

### 7.1 推荐保留的在线命令

- `#SPD=`：设置速度档
- `#RUN!` / `#STOP!`
- `#STAT!` / `#HB`：输出状态
- `#CAL!`：MPU 零偏校准（gyroZOffset / gzo）
- `#TRIM=±N!`：手动微调
- `#AT=0/1`：自动 trim 开关
- `#HP=`：HEADING_PWM_GAIN
- `#HD=`：HEADING_YAWRATE_DAMP
- `#HS=`：HEADING_CORR_SLEW_STEP
- `#DB=`：deadband

### 7.2 一套推荐实验流程（每次只改 1 个量）

1. `#STOP!`
2. `#CAL!`（让车静止，完成零偏）
3. `#SPD=3`（或你当前常用速度）
4. `#TRIM=0!`，`#AT=1`（先让系统自己学）
5. `#RUN!`
6. 观察 10~30s 的 `HB/STAT`：
   - 是否 `yaw` 慢慢漂
   - 是否 `encoderDiff` 有持续偏差
   - `trimAuto/trimPwm` 是否缓慢收敛
7. 若左右摆动多：优先调 `HD/HS/HP`，不要先调大 `DB`。

## 8. 串口与硬件调试经验（很容易被忽略，但影响最大）

### 8.1 串口不出数据的第一优先级检查

- TX/RX 是否接反（最常见）。
- 是否共地。
- 波特率是否一致（115200）。
- 是否选对串口号（例如 COM8）。

### 8.2 MPU 读取失败的表现与处理

- 表现：`mpuReadFailCount` 增长、yaw/yawRate 不更新。
- 处理：
  - 先让系统在 mpu fail 时不做外环更新，避免用“脏数据”纠偏。
  - I2C 线长、上拉、电源噪声都可能导致间歇失败。

## 9. STM32 编译 + 烧录经验（让迭代变快）

### 9.1 编译（Keil ARM）

PowerShell 推荐写法：

- 用 `&` 调用 exe，避免 `-b` 被 PowerShell 误解析。
- 必查 `Objects/project.build_log.htm`：
  - `0 Error(s)`
  - `creating hex file`

### 9.2 烧录（STM32CubeProgrammer CLI + ST-LINK）

推荐参数：

- `port=SWD freq=4000 mode=UR reset=HWrst -w xxx.hex -v -rst`

失败优先处理顺序：

1. `mode=UR reset=HWrst`
2. 降低 `freq`
3. 检查 SWDIO/SWCLK/GND/3V3
4. 确认烧录的是最新 hex（时间戳检查）

## 10. 最小可行收敛策略（避免“转圈/掉头”）

当你遇到“后期突然发散/转圈”，优先做以下“止血”策略，再继续优化：

- 降低 `HP`（注入强度），让差速不要一脚打满。
- 加 `HD`（阻尼），减少摆动反复。
- 增加 `diffPwm` 限幅（不要超过电机可控区间）。
- 保留 `HS` 平滑，确保 headingCorr 不突变。
- DB 不要盲目增大，DB 太大更容易“晚介入→大动作→发散”。

## 11. 实车验证清单（建议打印/照着跑）

- [ ] `#CAL!` 后 gzo 合理且稳定
- [ ] `mpuReadFailCount` 不持续增长
- [ ] `yawErr` 与纠偏方向一致（不是正反馈）
- [ ] `diffPwm` 变化能反映到左右 PWM 差值
- [ ] 不频繁饱和（PWM / diffPwm 打满）
- [ ] `auto-trim` 在稳定行驶段缓慢收敛，`trimPwm` 不乱跳
- [ ] 手动 `#TRIM=` 会触发 manual override，`#AT=1` 可恢复自动学习

## 12. 版本管理建议（防止越改越乱）

- 每次改动只做一类事情：
  - 只改观测输出 / 只改符号 / 只改一个参数默认值 / 只改一个策略。
- 保留“可回退的基线版本”（能稳定跑但不够直，也比发散强）。
- 每次路测保存：
  - 当时参数（HP/HD/HS/DB/trim）
  - 关键现象描述
  - 一段 HB/STAT 日志（10~30s）
