# 串口命令行调试参数手册

## 1. 文档说明

本文基于当前工程 `Project_Refactor/Hardware/Control.c` 的实际命令解析逻辑整理，专门用于现场查阅串口 CLI 命令。

适用前提：

- **[工程]** `Project_Refactor`
- **[串口端口]** `COM18`
- **[波特率]** `115200`
- **[调试模式]** 默认建议先切回文本模式 `#VOFA=0!`

> **安全警告**
> 
> 发送 `#RUN!`、`#EXP=RUN,...!`、`#RAW=...!` 前，必须先确认小车已架空或处于安全试验区。

---

## 2. 通信配置

### 2.1 串口参数

当前建议统一使用：

- **[端口号]** `COM18`
- **[波特率]** `115200`
- **[数据位]** `8`
- **[停止位]** `1`
- **[校验位]** `None`
- **[流控]** `None`
- **[命令编码]** ASCII 文本

### 2.2 命令发送规则

- 每条命令以 `!` 结尾
- 固件接受形如 `#CMD!` 或 `#KEY=VALUE!` 的命令
- 当前代码中部分无 `!` 版本也会兼容，例如 `#RUN`、`#STOP`、`#STAT`、`#CAL`、`#IMU_INIT`
- 但现场建议统一发送带 `!` 版本，避免歧义

### 2.3 返回格式总览

当前常见回包有以下几类：

- **[确认回包]** `OK xxx`
- **[错误回包]** `ERR`
- **[状态回包]** `STAT ...`
- **[配置回包]** `CFG ...`
- **[实验生命周期]** `EXP_START ...`、`EXP_END ...`、`EXP_TIMEOUT ...`
- **[实验导出]** `EXP_DUMP_BEGIN ...`、`FIELDS:...`、`D ...`、`EXP_DUMP_END ...`
- **[跟踪信息]** `TRACE ...`

> **注意**
> 
> `STAT`、`CFG`、`HB`、`EXP_DUMP` 等文本诊断信息依赖文本模式。若你切到了二进制 `VOFA` 模式，建议先发送 `#VOFA=0!` 再做串口文本调试。

## 3. 命令清单

## 3.1 基础控制命令

| 命令格式 | 功能说明 | 参数示例 | 返回值说明 |
| --- | --- | --- | --- |
| `#RUN!` | 启动双环控制 | `#RUN!` | 成功时返回 `OK RUN`，通常还会有 `TRACE RUN_CMD`、`TRACE RUN_OK`，并在文本模式下附带 `CFG ...`；失败返回 `ERR` |
| `#STOP!` | 停止控制并关闭电机输出 | `#STOP!` | 返回 `OK STOP` |
| `#STAT!` | 输出当前完整状态快照 | `#STAT!` | 返回一行 `STAT ...`，包含 `yaw`、编码器、PID、死区、起步偏置等完整字段 |
| `#CAL!` | 锁定当前航向为参考航向 | `#CAL!` | 返回 `OK CAL` |
| `#IMU_INIT!` | 重新初始化 IMU（当前为 BNO085 驱动分支） | `#IMU_INIT!` | 成功返回 `OK IMU_INIT`，失败返回 `ERR` |

## 3.2 VOFA / 遥测模式命令

| 命令格式 | 功能说明 | 参数示例 | 返回值说明 |
| --- | --- | --- | --- |
| `#BIN=0!` | 切回文本 `FireWater` 模式 | `#BIN=0!` | 返回 `OK BIN` |
| `#BIN=3!` | 切到 `JustFloat3` 模式 | `#BIN=3!` | 一般返回 `OK BIN` 后切换；切换后不建议继续做文本诊断 |
| `#BIN=5!` | 切到 `JustFloat5` 模式 | `#BIN=5!` | 同上 |
| `#VOFA=0!` | `#BIN=0!` 的别名，切回文本模式 | `#VOFA=0!` | 返回 `OK VOFA` |
| `#VOFA=3!` | `JustFloat3` 模式 | `#VOFA=3!` | 返回 `OK VOFA` 后切换 |
| `#VOFA=5!` | `JustFloat5` 模式 | `#VOFA=5!` | 返回 `OK VOFA` 后切换 |

### 当前代码中二进制通道的真实含义

#### `#VOFA=3!` / `#BIN=3!`

当前 `Control.c` 实际输出 3 个浮点通道：

1. `actualAngle`
2. `actualSpeed`
3. `pwmCommand`

#### `#VOFA=5!` / `#BIN=5!`

当前 `Control.c` 实际输出 5 个浮点通道：

1. `targetAngle`
2. `actualAngle`
3. `actualSpeed`
4. `speedOut`
5. `angleOut`

> **注意**
> 
> 这里必须以当前代码为准，不要照搬旧分支中“输出 yaw/左右轮速度”的旧文档。

| `#ENC_L_SIGN=-1!` | 设置左编码器反方向 | `#ENC_L_SIGN=-1!` | 返回 `OK ENC_L_SIGN` |

## 3.4 实验控制命令

| 命令格式 | 功能说明 | 参数示例 | 返回值说明 |
| --- | --- | --- | --- |
| `#EXP=START,id,ms!` | 只启动实验记录上下文，不自动运行电机 | `#EXP=START,101,10000!` | 会先输出 `EXP_START id=101 ms=10000`，随后返回 `OK EXP_START` |
| `#EXP=STREAM,en!` | 开关实验流式输出 | `#EXP=STREAM,1!` | 返回 `OK EXP_STREAM` |
| `#EXP=RUN,id,ms!` | 一键执行实验：创建实验、锁航向、启动控制 | `#EXP=RUN,101,10000!` | 典型顺序为 `EXP_START ...`、`OK EXP_START`、`OK CAL`、`OK RUN`，文本模式下还会附带 `CFG ...` |
| `#EXP=STOP,id!` | 停止指定实验并允许后续导出 | `#EXP=STOP,101!` | 若实验活动且 ID 匹配，会先输出 `EXP_END id=101`，随后返回 `OK EXP_STOP`；否则 `ERR` |
| `#EXP=DUMP,id!` | 导出实验缓存数据 | `#EXP=DUMP,101!` | 典型顺序为 `EXP_DUMP_BEGIN id=101`、`FIELDS:...`、若干 `D ...` 行、`EXP_DUMP_END id=101`，最后 `OK EXP_DUMP` |

## 3.6 起步偏置与死区调试命令

| 命令格式 | 功能说明 | 参数示例 | 返回值说明 |
| --- | --- | --- | --- |
| `#DZ=n!` | 同时设置左右统一死区补偿 | `#DZ=10!` | 返回 `OK DZ`，同时更新 `DZL/DZR` |
| `#DZL=n!` | 设置左侧死区补偿 | `#DZL=10!` | 返回 `OK DZL` |
| `#DZR=n!` | 设置右侧死区补偿 | `#DZR=12!` | 返回 `OK DZR` |
| `#DZT=x!` | 设置死区阈值 | `#DZT=1.0!` | 返回 `OK DZT` |
| `#SBF=n!` | 设置起步偏置幅值 | `#SBF=2!` | 返回 `OK SBF` |
| `#SBV=x!` | 设置起步偏置退出速度阈值 | `#SBV=18!` | 返回 `OK SBV` |
| `#SIV=x!` | 设置速度积分启用阈值 | `#SIV=18!` | 返回 `OK SIV`，并重置速度环状态 |
| `#HDT=n!` | 设置航向环延迟介入时间，单位 ms | `#HDT=400!` | 返回 `OK HDT` |

### `#SBF=` 的方向说明

当前代码的实际含义是：

- `#SBF=正值!`：前进时**补右轮**
- `#SBF=负值!`：前进时**补左轮**

因此，现场调整必须结合 `#STAT!` / `HB` 中的 `el/er`、`OL/OR` 一起判断。

## 3.7 开环原始输出命令

| 命令格式 | 功能说明 | 参数示例 | 返回值说明 |
| --- | --- | --- | --- |
| `#RAW=n!` | 进入原始开环输出模式，`n` 范围约 `-100~100` | `#RAW=20!` | 返回 `OK RAW`，立即使能电机，绕过正常双环控制 |
| `#RAW=0!` | 退出原始开环输出模式并停机 | `#RAW=0!` | 返回 `OK RAW0` |

> **安全警告**
> 
> `#RAW=` 会直接驱动电机，不经过正常双环调节。首次试验必须从小值开始，并确保车体架空。

## 4. `STAT` / `CFG` / `HB` 常看字段

## 4.1 `STAT ...` 重点字段

当前 `#STAT!` 会输出一行很长的 `STAT ...`，常用字段如下：

- **[运行状态]** `run`
- **[目标速度 / 实际速度]** `spd`、`ts`、`as`
- **[姿态环]** `ta`、`aa`、`ae`、`ao`
- **[偏航]** `y`、`yr`
- **[输出]** `L`、`R`、`OL`、`OR`
- **[编码器]** `el`、`er`、`ed`、`dl`、`dr`、`cl`、`cr`
- **[PID 参数]** `skp`、`ski`、`skd`、`akp`、`aki`、`akd`
- **[起步偏置 / 死区]** `dz`、`dzl`、`dzr`、`dzt`、`sbf`、`sbo`、`sbv`、`siv`、`hdt`
- **[IMU 状态]** `who`、`addr`、`icm_ok`、`icm_fail`
- **[遥测状态]** `vofa`、`rx`、`txdrop`

## 4.2 `CFG ...` 的用途

`CFG ...` 常在 `#RUN!` 或 `#EXP=RUN,...!` 成功后输出，适合确认：

- 当前 PID 是否为预期值
- 当前死区与起步偏置参数是否已经生效
- 当前是否处于 `vofa=firewater`

## 4.3 `HB ...` 的用途

`HB ...` 是运行期心跳记录，适合：

- 长时间抓取偏航与编码器趋势
- 给 `trajectory_analyzer.py` 做轨迹复盘
- 配合 `exp_runner.py` 自动生成 `*_windows.csv` 与 `*_trajectory.csv`

## 5. 常用调试场景

## 5.1 查看当前完整状态

### 目的

快速确认 IMU、编码器、PID、死区、起步偏置等当前值。

### 命令

```text
#VOFA=0!
#STAT!
```

### 重点看

- `who` 是否正常
- `y / yr` 是否稳定
- `el / er / ed` 是否合理
- `dzl / dzr / sbf / sbv / siv / hdt` 是否为预期值

## 5.2 不用 `trim` 的起步偏置调试

### 目的

解决起步前段轻微偏航，但**禁止**使用 `trim`。

### 建议顺序

```text
#VOFA=0!
#CAL!
#DZL=10!
#DZR=12!
#SBF=2!
#SBV=18!
#SIV=18!
#HDT=400!
#STAT!
#RUN!
```

### 判断方法

- **[编码器先失衡]** 先调 `DZL/DZR`
- **[输出先失衡]** 再调 `SBF`
- **[猛冲]** 调 `SIV`
- **[像被硬拉方向]** 调 `HDT`

## 5.3 快速 IMU 复位与重初始化

### 适用情况

- 上电后偏航异常
- `STAT` 中 `who/addr` 不正常
- 长时间测试后需要重新确认 IMU 状态

### 命令

```text
#STOP!
#IMU_INIT!
#CAL!
#STAT!
```

### 预期

- 返回 `OK IMU_INIT`
- `STAT` 中 `who=0x85`

## 5.4 开环快速电机试验

### 适用情况

- 快速确认电机能否被驱动
- 排查“闭环没起效”和“电机根本没动”之间的区别

### 命令

```text
#RAW=15!
```

停止：

```text
#RAW=0!
#STOP!
```

### 注意

当前固件没有“单独左轮 / 单独右轮 RAW 输出”命令，`#RAW=` 只适合做双侧统一开环试验。

## 5.5 一键实验采集与导出

### 启动实验

```text
#VOFA=0!
#EXP=STREAM,1!
#EXP=RUN,201,10000!
```

### 停止与导出

```text
#EXP=STREAM,0!
#EXP=DUMP,201!
```

### 典型返回

```text
EXP_START id=201 ms=10000
OK EXP_START
OK CAL
OK RUN
CFG ...
...
EXP_DUMP_BEGIN id=201
FIELDS:...
D ...
EXP_DUMP_END id=201
OK EXP_DUMP
```

## 5.6 “重置编码器”的替代做法

当前固件**没有单独的串口编码器复位命令**，但以下操作会在固件内部调用 `Encoder_Reset()`：

- `#STOP!`
- `#RUN!` / `#EXP=RUN,...!` 启动流程

因此若现场需要“相当于清零编码器再测”，建议使用：

```text
#STOP!
#CAL!
#RUN!
```

或：

```text
#STOP!
#EXP=RUN,301,8000!
```

## 6. 当前固件**不支持**或不建议使用的命令/做法

以下内容不要写入你的现场常用命令模板：

### 6.1 不支持的旧分支命令

| 命令 / 做法 | 当前状态 | 说明 |
| --- | --- | --- |
| `#TRIM=...!` | **当前固件不支持** | 当前 `Control.c` 没有 `#TRIM=` 解析入口 |
| `#PWM_MAX=...!` | **当前固件不支持** | `exp_runner.py` 中存在兼容发送逻辑，但当前 `Control.c` 未实现解析 |
| `#DIFF_MAX=...!` | **当前固件不支持** | 同上 |
| `#AT=...!` | **当前固件不支持** | 当前分支未在 `Control.c` 命令入口实现 |
| 单独编码器复位命令 | **当前固件不支持** | 需通过 `#STOP!` / 重新启动流程间接完成 |

### 6.2 不建议的做法

- **[不建议]** 在二进制 `VOFA` 模式下做 `#STAT!`、`#EXP=DUMP!` 这类文本诊断
- **[不建议]** 起步偏置问题一上来先猛调 PID
- **[不建议]** 没有架空小车就直接发 `#RAW=`

## 8. 结论

当前 `Project_Refactor` 工程的串口 CLI 使用原则很明确：

- **[串口统一]** `COM18`，`115200 8N1`
- **[文本诊断优先]** 调试前先 `#VOFA=0!`
- **[起步偏置禁止 `trim`]** 当前分支只允许走 `DZL/DZR/SBF/SBV/SIV/HDT`
- **[命令手册以 `Control.c` 为准]** 不要把旧分支或旧脚本里出现过、但当前固件未实现的命令当成可用命令

只要按照本文的命令表执行，现场调试、状态核对、实验导出和起步偏置整定就可以统一在一套稳定的串口工作流中完成。
