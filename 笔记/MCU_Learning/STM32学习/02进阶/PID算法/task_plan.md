# 421 循迹速度链与弯道增强参数收敛计划

## 目标

解决 `Project_Refactor_track-421 - 副本 (2)` 在 `TRACK` 模式下“速度慢、左右晃、轮端一卡一卡”的问题，并验证弯道增强参数是否值得保留。

## 阶段

- [completed] 1. 核对当前循迹控制链与日志指标
- [completed] 2. 重构 TRACK 速度链与轮端输出收敛策略
- [completed] 3. 编译烧录并校验当前固件
- [completed] 4. 围绕弯道增强组做二分调参与在线复测
- [completed] 5. 恢复当前默认参数并准备提交 Git

## 当前结论

- 当前慢速与顿挫的主根因是 `TRACK` 速度斜坡、轮端死区补偿、轮端限幅三层控制互相打架，而不是单纯 `KP/KD` 不够。
- 已把 `TRACK` 改回“快斜坡但不直通目标速度 + 双轮各自过死区 + 双轮斜率限制”，并在中心区限制差速预算，减少单轮反复掉进死区。
- 围绕弯道增强组 `35.64 / 0.04 / 0.62 / 0.68` 做了二分；`0.5 / 0.25 / 0.125` 三个中间点都不如默认组稳定，说明这条增强方向本身不该继续作为主线。
- 当前板端已恢复到默认组 `33.0 / 0.05 / 0.72 / 0.63`，后续若继续调参，应换到别的维度，比如 `TTR / TCA0 / TDB0` 或重新做更稳的弯中保底速度搜索。
